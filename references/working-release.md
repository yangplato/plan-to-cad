# 从工作稿到可接手的首稿

绘图者运行 `python scripts/run_first_plan.py JOB.json 工作目录`。交给独审者同一原图、`review/native/plan.dwg`、叠图和 `review/首稿试印.pdf`。先让审图者在原图独立点出墙、门洞、相邻物件的应接边和有意留空，再看脚本的已登记结果。原图有同页小图时记录其用途。冻结独立首稿 DWG 与哈希。若安排人工 DWG 对照，把对照发现另存。图片稿的修订证据来自营销图和原生回读。一个户型默认两人分工。无人独审时标记“已自检，待独审”。

先稳定墙、门窗、敞口与源图控制，再放家具，避免用家具遮住结构缺项。同版同哈希的原生回读可供多项检查复用；改图后重新回读受影响版本。结构、可编辑性与实际纸面均为交付门槛。既有授权内的修正和复核直接完成，不再增加阶段确认。

## 验图

1. 逐一对应印刷标数及其两端。未标墙位记录是按哪一侧齐平或哪一个构造关系推定。原生 DIMENSION 必须实改定义点再核显示数字。
2. 查看实墙两面与闭合填充。洞口无穿墙，窗两端接洞侧，门套、门扇、通行方向和净宽合理。相邻门垛和卫生间入口一并看。收口共边查实际长度。
3. 调出 `review/object-edge-relations.json`。逐项从物件实际功能边与对侧实物量间隙、共边和侵入。分别登记接触长度与露边。转角柜兼查两翼，排柜兼查两端，设备兼查相邻模块及门扇。每一组有意留空的物件查使用净距。复开副本分别关闭家具两层，再恢复。从结构视图检查门、窗及墙线是否仍完整。
4. 先实量PDF页面与一段已知长度，再看整页和正常阅读局部。`Plan-A3`内保留真实图框、图签、图例、必要房名及锁定视口。图签的来源、版本、日期、比例、单位与限制须齐全。项目线宽示例为墙0.40／0.35、固定家具0.25、活动家具及窗0.20、门0.18、尺寸0.15、细部0.13 mm；两级灰填充不能遮细线。数字纸面字高2.5 mm只是项目选值，汉字按实际字体及可读性另核。脚本按范围选比例，可用`scene.paper.scale`指定。样式值不能代替真实PDF检查，压字、符号冲突、留白不足或图签缺项均需返修。
5. `plan_sheet.py`校验原生回读的DWG及DXF哈希，从真纸空间及锁定视口导出同版矢量PDF。命令为`python scripts/plan_sheet.py 原生回读目录 输出.pdf`，可加`--ctb 路径`。PDF由ezdxf和PyMuPDF生成，不冒称AutoCAD打印驱动输出；旧案驱动失败记录不作为所有环境的事实。软件、字体、CTB、实际打印机分别按本次环境核实。导出后必须由执行者实际看图，记录整页、正常阅读局部和未解决项。

V1.2作业把原图参照放入A-XREF层；旧版冻结作业保留10-原图参照。需要只显示主户型区域时，设置 `job.reference_clip_px`，保留原文件用于追查。房名在模型空间；图框、图签、图例和锁定视口在Plan-A3布局。签署本版独审或修订稿复查时，在下列 JSON 的顶层同时填入 `professional_review`、`overlay_review` 两项。包括二者的字段和 SHA-256 绑定见[整户专业审查](professional-review.md)。历史作业按原版本复验。

## 独审返回什么

记录复开的 DWG 哈希、审图者、按实际比例看到的情况、具体问题。可直接照以下格式填独审 JSON。一个确认错误占一项。`evidence` 写明依据来自原图、叠图或本次 DWG 的实际端面。证据足够且在本次复刻授权内的错误记为 `repair`。可按原图现状保留的构造记为 `inference`，说明保留理由。仍有多个实质不同的合理解，或会越过用户已确认的标数、结构控制面或布局时记为 `decision`，写清证据缺口和各选择的影响。

```json
{"dwg_sha256":"本次 DWG 的 SHA-256","reviewer":"独审者","paper_observation":"注明此图最密尺寸链及墙、家具、门弧是否可辨","issues":[{"id":"柜-东","kind":"repair","location":"中卧衣柜东端","finding":"端板应贴东墙","evidence":"复开后量得有缝，请附定位或实量"}]}
```

绘图者一次集中修正已确认的问题，在新临时目录重建。审图者填复查 JSON。每个 ID 只占一行，记录改动后的实量和所有受影响的邻件。如出现新的实质错误，在 new_defects 中写位置和问题。仍需用户决策的事项单列。脚本只关联审图记录和实际文件，人负责从图纸判定遗漏、功能与可读性。

```json
{"original_sha256":"首次独审的哈希","dwg_sha256":"改后哈希","reviewer":"独审者","paper_observation":"改动位置及同页尺寸清晰","repairs":[{"id":"柜-东","result":"fixed","measurement":"实量接缝及共边","affected_checks":["背边、邻门、关层、邻柜端面"]}],"new_defects":[]}
```

```sh
python scripts/review_working_plan.py 工作目录 独审.json
python scripts/review_working_plan.py 工作目录 独审.json --revised 改后目录 --recheck 局部复查.json
```

无确定错项时，只执行第一条。返回“可交设计师接手”表示完成本流程。仍有确认错项或待决事项时，按返回状态交代，不继续启动修改轮次。遇到“待局部复核”，按 pending_checks 的具体位置看原图和已存 CAD。确认为有意留空、正常上下叠放或脚本无法量的轮廓，可在本版独审或复查 JSON 的 measured_exceptions 中填 id 和 evidence，给出实际边、长度或局部图。确有侵入、应接缝或原生尺寸失败时，回到工作稿集中修正。未独审时标明状态。

任何脚本返回都不扩大已查范围。已知失败先于待核和通过项报告；修好后从新终稿复量原截线及另一条受影响约束，纸面随版本重出并实看。原图控制、墙面及空间清单由本案独立枚举，不固定套用历史数量。真实缺陷的回归小样留在测试或本案证据中，不把具体户型尺寸写成通用规则。

审稿预期与绘图预期逐ID比较。新结果只能替换同版、明确覆盖且实际通过的旧项。未覆盖的已知失败或待核项保留；清单范围变化列待核。新的待核结果不能清掉旧失败，通用手测说明也不能豁免源图实体检查。

同等质量下评估人工省时，可加 `--timing 计时.json`。记录 equivalent_scope_quality、manual_active_min、handover_active_min，可另记 background_min。接手用时包括看图、量图、拉墙、移门、调家具和最终确认。后台耗时单列。按 1－接手分钟／同范围从零分钟计算。无真实记录写“待测”。

每案完成后，按[轻量经验](experience.md)从明确输入生成一份`作业复盘.md`。它只记录本案方法、证据和限制；无新增经验只写一行引用。不得据“0错误”杜撰通过，不自动晋升通用规则或写全局记忆。
