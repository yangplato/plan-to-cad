# 按真实接边放家具

先看原图。逐件指出哪一面是背面、端面或侧面，哪一面应贴墙，哪一面接另一件家具，哪一面要活动或留安装缝。厨房一排柜按实物拆开。登记第一件的外端、连续模块之间的每条缝和最后一件的外端。一个物件可以同时受多面限制。图上不能判断的边用 `unknown`，留给原图与原生局部的人工复核。

## 家具表写法

沿用 `objects.json` 已有的物件、尺寸、厚度、朝向与角色。以下字段追加到同一件家具。`side` 是从家具向外看的模型空间法向。`+x` 朝东，`-x` 朝西，`+y` 朝北，`-y` 朝南。斜放物件对斜放邻件也可填实际向外的 `[nx, ny]`。在 `basis` 写清背、端、侧的实际含义和来源。

```json
{
  "id": "west-cabinet",
  "type": "hosted",
  "family": "cabinet",
  "role": "fixed",
  "host": "north-wall",
  "side": "-y",
  "near_px": [310, 124],
  "width_mm": 1400,
  "depth_mm": 560,
  "edge_relations": [
    {"side":"-x", "target":{"wall":"west-wall"}, "basis":"西端抵西墙内面"},
    {"side":"+x", "target":{"object":"middle-appliance"}, "basis":"东端接中间设备西侧板"}
  ],
  "edge_adjustment": {"width_axis":"x", "min_width_mm":1250, "max_width_mm":1600, "basis":"此段是可按净宽下料的定制柜"},
  "free_sides": {"-y":"南面朝操作通道"}
}
```

`hosted` 的真实背面继承 `host` 与 `side`。L 形柜也继承 `return_host`。墙材分段时可给同一平面的 `target.walls` 数组。对 `outline`、`fixture`、`family` 或库块，在 `edge_relations` 明写已看清的每条接触。不要只填一条背边。相邻两件只需登记一次，程序同时核实两侧。另一个物件只作为参照时，其位置固定。多个受约束的活动件、带柜端的柜列会一起求解。

| 原图关系 | `kind` 与附加字段 | 实际处理 |
|---|---|---|
| 贴墙或接柜 | `touch`，默认值 | 求共同面。贴墙默认要支持整条选定边；柜间默认取两条实体边中较短一条的长度。 |
| 有意安装缝 | `clearance` 和正数 `gap_mm` | 按原图或技术依据保持法向净距，测量两边实际正对的长度。 |
| 真正的柔性切点 | `soft_point` | 测实际外轮廓的端点或切点是否落在对面有效范围。保留刚体穿插检查。圆弧离散精度不足时另作原生局部核验。 |
| 看不清是否应接 | `unknown` 和 `basis` | 保留待判，按观察补充。 |
| 已证实可活动的近邻面 | `free_sides` 中写该面的依据 | 保留原位置，继续检查碰撞。 |

原图中独立摆放的成品可一次写 `"freestanding_basis":"餐桌居中，四把椅子可拉动，四周为走道"`。写在 `dining` 上会传给这张桌和生成的所有椅子。远离邻面的浮置件不需逐写四个自由面。靠近墙或其他物件而用途尚未判明的局部仍会列出。已有接边、故意留缝、真实互穿和轮廓不明都会照常检查。

成品只平移。不给 `edge_adjustment` 就不改尺寸。规则只允许明确为可定制的固定直柜或矩形自定义件在规定范围内沿一轴伸缩，并优先尝试保持原宽。需要保留原图所定端点时给 `fixed_sides`，例如 `["-x"]` 保留西端、`["center_x"]` 保留横向中心。固定这些原位需有原图实据。两端要收墙时分别声明两面；一排柜中间的固定宽度电器可用两侧柜调整来消化净宽差。整体无解或求解后碰墙、碰相邻物件、挡门时，回看模型和观察。

凹柜、错台或有多条同向端边时，在同方向分别写多条规则并给不同 `id`。用 `edge: {"member_path":["实际块内图元句柄"],"segment":2}` 选实际边。另一件的边可放在 `target.edge`。直线不需要 `segment`。嵌套块把沿途的块参照句柄写在 `member_path` 前面。零件含装饰、软环或非闭合线时，可用 `edge_physical_outlines` 指定实际完整占地，采用 `align_furniture_to_wall.py` 的 `path` 和 `parts` 写法。未能识别实际占地的物件保留待核。真实设计只需短段接触时，写 `min_shared_mm` 并给出依据。

## 分辨真正承担接合的部件

登记前后都要在同一坐标系检查两侧的实体。靠窗书桌可同时有桌板、侧柜及曲线饰件。按桌板或实际安装边计算安装余量；装饰末点与窗线相碰时，记录其独立接触。柜端或梳妆台只有一部分贴邻柜时，分别登记共边和伸出的长度。墙垛与门轨位于同一直线上时，依两者的各自起止端分段；内嵌水槽、电器或背后的墙不会自动成为该柜端的承接物。

## 保存和复开

共同出图入口写 `edge-relations.json` 与 `edge-placement.json`。原生复开后从当前块参照、实际闭合轮廓和扣洞墙材重新计算每条关系。毫米、平方毫米和图元句柄均可查。`normal_gap_mm` 为带符号法向净距；负值表示越过目标平面。`projected_shared_mm` 为两条实际边在切向上重合的长度。只有实际贴到目标面才计入 `physical_shared_mm`。两个有限线段即便共线，只要错开或只相碰一个角，就不能通过整边接触要求。

复查报告 `review/object-edge-relations.json` 列出每件的接边、对象与实墙或其它物件的正面积交叠、需要复核的近邻实墙或物件，以及无对应支承记录的固定件。默认在 75 mm 内列候选，可在 `scene.json` 用 `edge_review_reach_mm` 调整。这个距离只影响候选提示，无近邻方向只作覆盖记录，已指定的目标即使更远也会求解和核量。凹口、斜边、遮罩、复合块须按原图补选各个实际面。已有桌下收椅、地毯、嵌入等合理投影从已登记的 `relations.json` 读取；一个已声明应对接的零件对仍会核互穿。旧表可以继续出图，尚未判断的近邻及固定件进入复核清单。

单独复量已登记的文件可运行以下命令。

```sh
python scripts/object_edge_relations.py review/native/readback.dxf ledger.json edge-relations.json measured-edges.json --projections relations.json
```
