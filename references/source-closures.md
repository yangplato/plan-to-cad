# 从原图复核敞口、门扇和铰侧

读图者和绘图者完成各自的 `source-reading.json` 后，对两份记录的洞口并集运行本项。即使两人都写敞口，或两人写了相同的铰侧和开向，也逐洞检查。输入格式见[独立读原图](independent-source.md)。两份清单用 `source_sha256` 绑定同一张原始图片。

```sh
python scripts/check_source_closures.py 原图.jpg 自读.json 独立读图.json 新输出目录 \
  --band-px 2.5 --mm-per-px 21
```

示例数字须换为本图原始像素的端点读差和比例。可用 `--stroke-px` 指定原图上的典型图符笔宽，默认 1.6 像素。已有[独立房间记录](physical-room-connections.md)时加 `--room-witness 房间记录.json`。程序只读其中的 `rooms[].id/mode`、`open_links` 和 `portals[].id/rooms`。给此文件提供 `source_sha256` 时，程序会核对它。没有房间记录也会检查每一处原图门弧和门扇。

## 看每个洞口

1. 打开 `source-closures.json`。每个 `locations[]` 项列出两人的原判断与像素检查结果。打开其 `panel` 查看原图、对比增强和像素命中点。按 `traces` 文件中的 `id` 找到全部候选。P 是铰点，C 是扇关闭时的端点，O 是扇打开时的端点。
2. 程序只用两人记录的洞口端点定位搜索区。它从未标记的源像素重新搜索八种正交姿态和不同半径。读图者给出的铰点、扇端、类型和房间名均不参与弧、叶评分。圆弧要有多段可见曲率，开扇要有连续直边。邻近半径、弧两端延伸和叶尖外延伸用于排除整圆、地板线或过长的柜线。两人只有共同错误的位置、或两人都遗漏的门区，仍须借助全图周界巡查发现。
3. 另以登记的 A、B 两端分别作铰，向两侧比较四种全宽单扇。每人的 `fixed_endpoint_hypotheses` 保留四组弧、叶强度和分段命中情况。浮动铰点搜索找到了完整的弧和叶，还要核实际闭合线能否落在本洞两端。两扇分别有弧有叶、各靠一端且关闭后在中间相遇，才列为互补双扇。两种搜索互相矛盾、一个弧可以解释为两个墙向、或另有未归属的扇时，逐处复读。
4. 检查敞口时，核对它连接的两个空间、地面是否穿过洞口、有没有门槛、窗框、推拉轨和其它可以闭合的构件。卧室、卫浴与可能通户外的边会单独提示。阳台需要再确认是否已封窗。空间名称仅用于提示复核对象。查看卧室套间是否实际共享开放空间，或外侧是否还有独立围护。依据现场使用推断的构件，在解答中注明推断及原因。
5. 对敞口，程序在洞宽 18% 至 82% 之间取五条穿洞短线。沿每条线读 RGB 三通道，保留各线最大色阶变化。五条线均完整且色阶变化都在 10 以内，表示这几处有同色地面穿过的迹象。独立房间记录还确认该开放关系、没有私密或室外疑问且本区没有弧候选时，才给出 `compatible_open`。同色地面的门也可能不画开扇。仍需在原图查门框、推拉轨、遮挡和周边闭合关系。

## 结果含义

| 状态 | 读法 |
| --- | --- |
| `conflict` | 源像素支持的完整扇在本洞闭合，但登记的类型、铰侧、开向或扇数与它相冲突。两份记录各自与图证比对。查看候选和原图，记录最终取舍。 |
| `supported` | 本洞的平开图符、各扇铰点和开扇端获得像素支持。宿主实墙和实际通行另由回读检查。 |
| `compatible_open` | 独立登记的开放关系与五处地面的原图色调相容。 |
| `review` | 可能缺门、缺少图证、门区太小、两轴都有依据、两份记录有差异，或同一门区存在相互竞争的候选。先看 `reasons`，再看候选的 `pixel_cautions`。 |
| `other_family` | 当前登记为推拉、窗或栏，此项没有发现与登记类型相冲突的完整平开扇。继续逐线检查框、轨、玻璃或栏杆。 |

`opposite_hinge_evidence` 表示实见铰点靠另一门垛。`opposite_open_side_evidence` 表示开扇指向墙轴另一侧。`leaf_count_conflict` 表示独立检出的扇数与登记不同。`complete_trace_nearby_but_span_or_axis_unconfirmed` 表示旁边有弧和叶，但未证实属于这个洞口。

搜索半径上限按洞宽和 1550 毫米取小值。能独立拟合的扇半径至少约 8.5 个原图像素。非正交、未达九十度的开扇，等亮异色线、特别细的小扇、透视变形、遮挡和搜索区外的实门均可能漏检。出现这些情形时，在原图重看门垛与可见曲线，必要时按[单洞复核](door-patch-card.md)扩大搜索。程序只输出证据和待核项，不自动改 CAD。

若弧很浅，门扇直边与家具线或窗边相接，另运行：
```sh
python scripts/compare_hinge_curves.py 原图.jpg 自读.json 独立读图.json 四种关门比较 --band-px 2
```
每个位置给一张无标线原图和四种假设图。A、B 分别为读图中的洞口两端，+、− 是宿主线两侧。假设的弧用短虚线表示。找能跟随原始弧中段、且左右端收束位置合理的假设。门弧圆心须位于实际铰点，弧线中段的凸向可区分靠左与靠右的铰点。每组三个或更多彼此分开的弧段同时贴合，比单个交点更有判别力。图中数字是六段弧的灰度差摘要；软装边、地纹或邻门也会产生灰度差。此图比较四种单扇假设，不给自动结论。完整双扇要分别查每扇及其关闭会合处。
